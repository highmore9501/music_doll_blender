# MusicDoll Blender

> **中文** | [English](README.en.md)

一个用于 Blender 的动画制作插件，用来帮助你把各种乐器的演奏动画装到角色身上。

## 它是怎么来的

我们之前给每种乐器都单独写了一个插件：吉他有吉他的插件，钢琴有钢琴的插件，小提琴又有小提琴的插件。

一开始这样做很直接，但用着用着就发现麻烦越来越多：

- 每种乐器都要重新做一遍"创建控制器、保存状态、生成动画、导入导出"这些事，代码重复得很厉害；
- 一个 Blender 文件里想放两个不同乐器的演奏者时，两套插件互不相认，很容易打架；
- 想给所有乐器加一个公共功能（比如修正手指骨骼），就得每个插件各改一遍。

所以我们决定换一种做法：**把所有的乐器都收进一个插件里**，由它统一来管理。这个插件就是你现在看到的 MusicDoll Blender。

它借鉴了我们在 Unreal 那边同一个名字的插件（MusicDoll）的思路：一个总框架负责公共部分，每种乐器作为其中一块，大家共用一套规则。

## 它是做什么的

简单说，MusicDoll Blender 可以帮你：

- **管理演奏者**：一个 Blender 文件里可以同时放好几个演奏者，吉他手、钢琴手、小提琴手都行。你可以从下拉菜单里随意切换当前在操作哪位，插件会自动记住每个人的骨骼、乐器、文件路径这些信息；
- **搭建控制器**：选好角色和乐器后，一键把整套控制用的物体创建出来，并且自动摆好层级、挂好父子关系。重复点也不会出乱子；
- **保存和读取状态**：把每个姿势（比如左手按住某个品、右手拨某根弦）存到角色的骨骼上，随时可以再读回来，方便反复调整；
- **导入导出数据**：把整理好的动作信息导出成文件（钢琴 `.avatar`、古筝 `.zheng_master`、架子鼓 `.drummer`、竖琴 `.harpist`、管乐 `.wind`、小提琴 `.violinist`、手风琴 `.accordion`、吉他 `.json`），交给我们的其他工具（Rust / Unreal 那边）继续用，也能把别人整理好的数据导回来；
- **生成动画**：读入动作数据文件，直接在 Blender 里给控制器和琴键打好关键帧，生成整套演奏动画；
- **提供小工具**：每种乐器都带一些实用工具，比如"修正手指骨骼"是所有乐器都能用的，"给吉他生成弦的变形形状"是吉他特有的，"给钢琴键做按下的变形形状"是钢琴特有的。工具都收在一个下拉菜单里，默认收起来，想用哪个选哪个，界面很干净。

## 现在支持哪些乐器

这个项目是分阶段合并进来的，目前已经包括 8 种乐器：

| 乐器 | 缩写 | 类型 | 数据后缀 | 说明 |
| ---- | ---- | ---- | ---- | ---- |
| FretDance（吉他） | FD | 移动乐器 | `.json` | 民谣吉他 / 电吉他 / 贝斯三套。左手按品、右手拨弦，电吉他可以打开颤音摇杆 |
| KeyRipple（钢琴） | KR | 固定乐器 | `.avatar` | 双手弹奏，支持黑键白键、高低把位，琴键按下的变形形状单独烘焙 |
| ZhengDrift（古筝） | ZD | 固定乐器 | `.zheng_master` | 21 弦，支持左右手状态、双脚、双线性映射、特殊朝向控制器 |
| BeatBloom（打击乐） | BB | 固定乐器 | `.drummer` | 鼓组演奏，由 DrumKit 配置驱动，左右手 / 双脚 + 头部朝向 |
| HarpGlide（竖琴） | HG | 固定乐器 | `.harpist` | 弦数可配（默认 47），支持双排弦。踏板、琴体倾斜、手部与头部姿势 |
| WindRise（管乐） | WR | 移动乐器 | `.wind` | 中式笛子 / 长笛 / 单簧管 / 萨克斯 / 竖笛，乐器名也可以自己填。状态按 midi 音高保存 |
| StringFlow（小提琴） | SF | 固定乐器 | `.violinist` | 小提琴 / 中提琴 / 大提琴三套。4 弦，数字命名手指，"手在弓上"结构，三点定平面琴弦工具 |
| BellowsPulse（手风琴） | BP | 固定乐器 | `.accordion` | 右手键盘或巴扬按钮 + 左手 Stradella。双键区枢轴、风箱极向、风箱开合姿态采样、分步属性面板 |

表格里的"移动乐器"指的是演奏者把乐器带着走（吉他、管乐），"固定乐器"是乐器在场上不动、靠人去找它（钢琴、古筝、架子鼓这类）。

所有乐器共用同一套公共机制（演奏者管理、状态存取、动画写入、导入导出、工具系统）。

## 怎么用

1. 安装：把 `src\` 目录改名成 `music_doll_blender` 后放进 Blender 的插件目录（比如 `Blender\5.0\scripts\addons\`）；也可以直接把 `src\` 目录压缩成 zip 拖进 Blender 的"偏好设置 → 插件"窗口自动安装；
2. 在 Blender 的"偏好设置 → 插件"里找到并启用 **MusicDoll Blender**；
3. 在 3D 视图右侧的侧边栏找到 **MusicDoll** 面板；
4. 在"角色选择器"里新建一个角色（名字 + 乐器类型 + 骨骼 + 乐器物体）；
5. 在对应乐器的子面板里点"Setup Objects"把控制器搭好，然后就能保存/加载状态、导入导出数据、生成动画了。

面板顶部是统一的"角色选择器 / 角色操作"区域，所有乐器共用；下面会根据当前演奏者的乐器类型，自动只显示对应的乐器子面板，以及一个可折叠的"工具"下拉菜单。

改完 `src/` 想重新打包一套给别人用，双击仓库根目录的 `build.bat` 就会生成 `music_doll_blender.zip`（顶层目录是 `music_doll_blender`，不含 `__pycache__`）。

## 给 agent 用的 skill

插件面板是给人用的：点按钮、摆姿势、存状态。但一个人物要从原始模型走到能在 Unreal 里演奏，中间还有一大段活落在面板之外：认出哪根骨是哪根、判断朝向对不对、量对齐误差、逐顶点比对形变有没有被改坏。这些活要的是现场判断加大量数值核对，我们现在把它们包成了几个 skill，交给 agent 在 Blender 的命令行里（`blender -b`）跑脚本，人只看结果和报告。

| skill | 管哪一段 | 现在能做什么 |
| ---- | ---- | ---- |
| `music-doll-rig` | 骨架改造 | 先把场景单位改成 0.01 米、把骨骼与网格放大 100 倍并应用缩放；再认链、造 MCH 主骨、把手臂 / 手指 / 腿的 Z 朝向对齐到规则方向、做 3% 拱形、加 IK 与复制旋转；最后补一条"腰→胸→颈"IK + 头部朝向控制链。三组断言验收，进度写回文件里的文本块，接手的人能接着干 |
| `music-doll-instrument-controls` | 装乐器控件 | MusicDoll 初始化 → 乐器 setup all objects → 让 `controller_root` 跟到人物的颈骨 / 胸骨 / 指定锚点 → 把实际控件的位置和旋转对齐到 test 控件 → 替换人物约束里的 test 引用 → 有头部控件的乐器顺手搭上半身朝向链 → 验收并清理。内置钢琴、古筝、架子鼓、吉他、手风琴、小提琴的适配器 |
| `music-doll-export-to-fbx` | 导出给 Unreal | 先过"单位 0.01 米 + 骨架在原点"的闸门，再把每个 mesh 分成骨骼网格 / 带形态键的部件 / 普通部件，判出它真实的父级（世界原点还是某根骨），烘焙到各自的导出空间，一个部件一个 fbx，并写一份 `manifest.json` 记录每个 fbx 该挂到哪儿。最后把这批 fbx 导回 Blender 逐顶点验收 |

整条链路是这样的，每一步都有自己的验收，前一步不过后面就不该往下走：

```
原始模型（MMD / Daz / 游戏拆包）
  │  music-doll-rig
  ▼
改造好的骨架 + test 控件（进度块 DONE）
  │  music-doll-instrument-controls
  ▼
能演奏的演奏者 .blend（乐器控件 + 上半身 / 头部链）
  │  music-doll-export-to-fbx
  ▼
一组 fbx + manifest.json  ──▶  Unreal（按清单组装演奏者）
```

最后一段"在 Unreal 里组装演奏者"的 skill 还在做。

技能包都放在仓库的 `skills/` 目录下，每个技能一个文件夹，里面是 `SKILL.md`（判据、实测数字、踩过的坑、完整命令）加一个 `scripts/`。用的时候把这个目录挂到 agent 的技能目录里（本机是 `~/.dsh/skills/`），做软链接最省事：仓库一改，agent 下次就用上新版。

脚本都是无头跑的，比如只想看看一个骨架的情况：

```powershell
blender -b --factory-startup -P skills/music-doll-rig/scripts/rig_analyze.py -- <模型.blend> --armature <骨架名>
```

`SKILL.md` 里有每个脚本的完整参数和验收口径。

这一套还在更新，目前的状态是：

- `music-doll-rig` 已经在四个不同来源的 MMD 模型上跑通，14 条链的验收断言全过；
- `music-doll-instrument-controls` 在同一个演奏者（米娅-星彩）的六个乐器版本上都装完并且独立验收通过了；
- `music-doll-export-to-fbx` 在架子鼓那份文件上导出了 5 个 fbx，回导验收 92 项全过；
- 还没实测的形态：控制器骨架（`Skirk`）、Rigify 版骨架、大提琴与竖琴的控件安装。

## 项目里都有什么

```
music_doll_blender/
├── src/                # 全部插件源代码（把此目录压缩成 zip 拖入 Blender 即可安装）
│   ├── __init__.py     # 插件入口，负责把公共部分和各乐器模块都装好
│   ├── common/         # 公共部分：所有乐器共用的规则和工具
│   │   └── tools/      # 公共工具（修正手指骨骼、骨骼/控制器映射、轴变换）
│   ├── fret_dance/     # 吉他模块（Phase 1）
│   ├── key_ripple/     # 钢琴模块（Phase 2）
│   ├── zheng_drift/    # 古筝模块（Phase 3）
│   ├── beat_bloom/     # 打击乐模块（Phase 4）
│   ├── harp_glide/     # 竖琴模块
│   ├── wind_rise/      # 管乐模块
│   ├── string_flow/    # 小提琴模块
│   └── bellows_pulse/  # 手风琴模块（Rust 端 bellows_pulse_rust）
├── skills/             # 给 agent 用的技能包（见上一节）
│   ├── music-doll-rig/
│   ├── music-doll-instrument-controls/
│   └── music-doll-export-to-fbx/
├── docs/plans/         # 施工方案（本机保留，不入库）
├── build.bat           # 打包脚本：src/ → music_doll_blender.zip
└── music_doll_blender.zip  # 分发包（本地生成）
```

- **common/** 是公共框架，相当于所有乐器的"地基"：怎么认识演奏者、怎么管理集合和物体、怎么读写状态、怎么写动画、怎么导入导出，都在这层统一实现，每个乐器直接复用；
- **fret_dance/ … bellows_pulse/** 是乐器模块，只放各自特有的东西：乐器的控制器布局、状态含义、导出格式、专属工具。

## 文档

- `skills/` 下三份 `SKILL.md` 是现在最完整的技术文档：判据、实测数字、失败案例、坑都在里面；
- 长篇的项目说明文档（架构、模块划分、数据模型、开发流程）和施工方案放在本机 `temp/`、`docs/plans/` 下，没有入库。

## 给谁用

主要面向我们自己制作音乐演奏动画的流程使用，也欢迎其他做乐器动画的朋友参考或使用。如果你只想快速给角色做一段演奏动画，用它搭控制器、摆姿势、生成动画会很省事；如果你也打算把演奏者送进 Unreal，那几个 agent skill 里的判据和坑可以直接拿去用。
