# MusicDoll 导出 FBX

## 这套东西解决什么

Blender 里的人物是一套控制体系：骨架、控制器方块、一堆中转空物体。UE 里没有这些——
**UE 的 mesh 不能挂到空物体上，只能挂到骨头上**。所以导出要做的事只有两件：

1. 把每个 mesh 的「真实父级」搞清楚：它到底是世界的固定物体（鼓台、凳子），还是跟着人物某根骨走
   （鼓棒跟手）；
2. 把每个 mesh 的坐标烘焙到对应的空间里，一个部件一个 fbx。这样 UE 那边按清单把 fbx 挂到骨头上（相对变换保持 0）
   或者直接摆原点，位置就都对得上。

**为什么要"烘焙"，不能原样导**：Blender 里鼓棒的父级是一个 8 顶点的控制器方块，方块又是空的子级。
这个父子关系进了 UE 没有对应物，会整条丢掉；而 mesh 自己的变换带着 100 倍缩放、父级逆矩阵这些东西，
原样导进去位置就飞了。烘焙就是把「它现在在世界里的样子」折进顶点，把物体变换清成单位矩阵。

## 什么时候别用它

- **单位还不是 0.01 米、骨架还没改造过**：先跑 `music-doll-rig`（它负责单位 + 缩放 + IK + 朝向）。本 skill 只检查，
  不替你改文件。
- **想连动画一起导**：这里明确不导动画（`bake_anim=False`）。演奏动画归别的流程。
- **场景里有第二个演奏者**：用 `--armature` 指定这一份导谁，不要一次导两个。
- **只想看结构、不动文件**：直接跑 `fbx_analyze.py`，它只读。

## 第 0 步：闸门（人先改，脚本不替人改文件）

导出前必须满足下面四条，任何一条不过脚本就直接退出（不写 fbx）：

| 闸门 | 判据 | 不过怎么办 |
|---|---|---|
| `unit_0.01m` | 单位系统 Metric、单位比例 0.01、长度 Meters | 属性编辑器 → 场景属性 → 单位，改成 Metric / 0.01 / Meters |
| `armature_resolved` | 场景里恰好一套骨架（或 `--armature` 指定） | 多套骨架时用 `--armature <名字>` |
| `armature_at_origin` | 骨架的位置 / 旋转 / 缩放都是 0 / 0 / 1 | 选中骨架，侧栏物体属性归零；有父级先 `alt+p` 清父级 |
| `skeletal_mesh_identity` | 骨骼网格自己的物体变换是单位矩阵 | 骨骼网格应当以骨架为父级且自身变换归零；**不要对它单独应用变换**（会破坏绑定） |

为什么卡单位：场景单位 0.01 米时 1 个单位 = 1 厘米，网格数字（身高 177）进 FBX 就是 177 cm，
UE 按厘米读正好 1.77 m。单位是 1.0 的话，同一份网格会被当成 177 米——这不是"偏一点"，是完全没法用。
实测 `辛焱_D_export.blend` 就是单位 1.0，闸门直接拒了（exit 2）。

为什么卡骨架原点：骨头的世界矩阵是「导出空间」的原点。骨架不在原点，导出的骨头坐标整体平移，
绑上去的鼓棒就跟着偏。

## 三类 mesh

`fbx_analyze.py` 先按结构判类，不靠名字：

| 类别 | 判据 | 怎么导 |
|---|---|---|
| **骨骼网格** | 带 `ARMATURE` 变形器、目标就是这套骨架 | 骨架 + 所有这类网格，一起导成**一个** fbx；骨架先切 `REST` |
| **带形态键的部件** | 有 shape key（Basis 之外还有别的键） | 单导网格（默认**不**连骨架，见文末「与计划文档的差异」）；形态键原样带走 |
| **普通部件** | 其它 mesh（乐器零件、凳子、鼓台…） | 单导网格，位置按「真实父级」烘焙 |

除了这三类，**其它一律不导**：空物体、灯光、摄像机、控制器方块。控制器方块也是 mesh（8 顶点、
没材质、在 `*Controllers_*` 集合里、常挂 Track To），不排掉它们会跟着混进 fbx——这就是为什么分类要走证据：

```
排除（实测：米娅那份文件排掉 29 个）
  · 在控制器集合里（集合名含 controller）                       → F_L / H_L / HP_L / I_L / ext_* / Head_Control …
  · 又小又光 + 挂跟踪/复制约束                                  → ext_* / Middle_Hand / Look_At
保留
  · 有材质 / 顶点多 / 有形态键 / 有变形器 / 有顶点组            → body / drum_kit / stool / stick_L / stick_R
```

集合名和「小方块」两个证据互相印证；只有其中一个时按部件保留，并在输出的「提醒」里点名，让人来看。

## 真实父级怎么判（这一步是整个 skill 的核心）

规则按顺序试，第一条命中就停：

1. **直接挂在骨上**（`parent_type == 'BONE'`）→ 就是那根骨。
2. **沿父链往上走，遇到一个物体的世界矩阵和某根骨重合** → 那根骨就是真实父级。
   这就是计划里说的「绑定到中转空物体、空物体再 copy location/rotation 到骨头」的情形：
   空物体和骨头的世界矩阵几乎相等，一比对就出来。
   实测两条路都验过：鼓棒直接挂在控制器方块 `H_L_Mia` 上 → 认出骨 `左手首`（误差 0.009 mm）；
   把鼓棒改挂到一个「Copy Location + Copy Rotation 自 `左手首`」的空物体上 → 仍然认出 `左手首`（误差 0.0001 mm）。
   阈值：平移 ≤ 1 mm 且旋转 ≤ 0.5°。
3. 父链走到顶都没有重合，且停在一个单位矩阵的物体上 → **世界原点**（鼓台、凳子就是这一类）。
4. 都不是 → 记为 `unresolved`，闸门不过，让人来改。

比对的是**当前姿势下的世界矩阵**，所以这一步必须在「骨真的跟着控制器走」的状态下算——
脚本会先把骨架切成 `POSE` 再算（文件原来是什么姿势不影响结果）。

**顺带会量一件很重要的事：这个部件是不是真的刚性跟着这根骨。** 同一个关系矩阵在两个不同帧上各算一次，
两帧之差就是漂移量（实测米娅的鼓棒 0.000 mm / 0.000°；超过 2 mm 就报「漂移！」）。
一个部件如果只是"大概在手上"，进了 UE 会随动画越走越远，必须在 Blender 里先修。

**一个必须报警的情况**：父链上有带变换的物体（比如某个控制器），却没有和任何骨重合。
这时脚本按「世界原点」处理并在「提醒」里点名——因为那通常是绑定的骨头被删了/改名了。
实测 `夜兰_D.blend` 的 `stick_R_yelan` 就是这样，Blender 自己也报
`Failed to add relation "Bone Parent" … Could not find op_from: ComponentKey(OBH_R_yelan, BONE, '手首.R')`。
这种 fbx 导出去，鼓棒进 UE 不会跟手，等于废的——必须在 Blender 里先把父级修好。

## 烘焙：两种空间，一个矩阵

对每个部件算一个「烘焙矩阵」，把它设成副本的物体矩阵，再应用进顶点：

| 真实父级 | 烘焙矩阵 | 应用后顶点坐标的含义 |
|---|---|---|
| 世界原点 | 网格自己的世界矩阵 `T` | 世界坐标 |
| 某根骨 | `B⁻¹ · T`（`B` = 那根骨的世界矩阵，`T` = 网格世界矩阵） | **骨骼空间**：原点在骨头、朝向是骨头的朝向 |

**为什么骨骼空间这条要乘上骨头的逆**：鼓棒的位置是"控制器在哪它就在哪"，而控制器和手骨在每一帧都重合
（实测 0.009 mm）。所以 `B⁻¹·T` 正好把姿势约掉了，不管当前在第几帧、手摆在哪，算出来的都是
「鼓棒相对这根骨的位置」这个不变量。实测跨 5 帧（1 / 100 / 5000 / 12730 / 15600）这个矩阵只动了
0.0001 mm 级——它就是常数。

进 UE 之后，把 mesh 挂到那根骨、相对变换留 0，位置就和 Blender 里一模一样。这就是清单里
`"attach": "socket_zero_offset"` 的意思。

## 手动做（GUI 里怎么走这一遍）

脚本做的是同一件事，想手点一遍或者核对脚本行为就照这个走。以「鼓棒挂在 `H_L_Mia` 上」为例：

1. 骨架切 `REST`（姿态模式 → 骨架属性 → 姿势位置 = Rest Position）；
2. 在姿态模式里选中 `H_L_Mia`，看它的世界坐标——它跟骨 `左手首` 是重合的（骨头的头就在那儿）；
3. 新建一个空物体，加 `Copy Location` + `Copy Rotation`，目标选骨架、子目标选骨 `左手首`
   → 空物体和这根骨对齐（也可以直接 copy 控制器 `H_L_Mia`，两者重合，结果一样）；
4. 选中鼓棒，`ctrl+p` → **Keep Transform Without Inverse**（父级换成这个空物体，此时位置不变）；
5. 把空物体上的两条约束禁用，再把空物体的位置 / 旋转 / 缩放归零——鼓棒会跟着跳一次，这是对的；
6. 选中鼓棒 `ctrl+a` → 应用 Location / Rotation / Scale。此时鼓棒的原点在骨头、顶点是骨骼坐标，
   物体变换是单位矩阵；
7. 导出这一个网格；
8. 还原：约束重新启用、鼓棒用 `ctrl+p` → Keep Transform Without Inverse 挂回原来的父级、删掉临时空物体。

三个坑：

- **第 5 步跳一次是正常的**，跳完就是骨骼空间；别在半路"觉得不对"把位置拉回去。
- **还原顺序反了会错位**：约束要先启用，再换父级，最后删空物体。手点容易漏，所以脚本用的是
  另一条路——复制一份网格 → 把烘焙矩阵设给副本 → 应用变换 → 导出 → 删副本。源物体一个字节都不动。
- **父级是世界原点的部件不需要空物体**：直接 `ctrl+a` 全部应用（位置 / 旋转 / 缩放）就是世界坐标。

## 跑脚本

```powershell
# 1) 只看：分几类、每个部件的真实父级是什么、闸门过不过（只读，不改文件）
& $blender -b --factory-startup -P "$skill\fbx_analyze.py" -- "<模型.blend>" --out "<输出目录>"

# 2) 导出：一个部件一个 fbx + manifest.json
& $blender -b --factory-startup -P "$skill\fbx_export.py" -- "<模型.blend>" --out "<输出目录>"

# 3) 验收：把这批 fbx 导回空场景，逐顶点 / 逐骨和源文件比
& $blender -b --factory-startup -P "$skill\fbx_verify.py" -- "<模型.blend>" --out "<输出目录>"
```

`--out` 不写时默认落在 `<模型所在目录>\<模型名>_fbx\`。退出码：`0` 通过，`2` 闸门未过，`3` 验收未过。

参数（三个脚本通用）：

| 参数 | 作用 |
|---|---|
| `--out <dir>` | 输出目录（analyze 在这里落 `plan.json`，export 落 `manifest.json`，verify 落 `verify.json`） |
| `--prefix <名字>` | fbx 文件名前缀。默认从骨架名推：`米娅-星彩_arm_Mia` → `米娅-星彩`，于是 `米娅-星彩_stick_L.fbx` |
| `--frame <n>` | 在哪一帧上判关系。默认当前帧（关系是不变量，换帧不改结论，但换帧能暴露漂移） |
| `--armature <名字>` | 场景里有多套骨架时指定导哪一套 |
| `--include A,B` / `--exclude A,B` | 强制纳入 / 排除某些对象（分类判错时用） |
| `--tolerance-mm` / `--tolerance-deg` | 「祖先和骨重合」的判据，默认 1 mm / 0.5° |
| `--stability-mm` / `--stability-deg` | 「两帧漂移」的判据，默认 2 mm / 0.5° |
| `--no-stability` | 跳过两帧比对（文件很大、想要快一点时） |
| `--morph-with-armature` | 带形态键的部件**连骨架**一起导（计划里的写法；默认不连，见文末） |
| `--unresolved fail\|world` | 父级判不出来时：失败（默认）还是硬按世界原点处理 |
| `--body-name <名字>` | 骨骼网格那个 fbx 的文件名，默认 `<前缀>_body` |
| `--dry-run` | 只演算不写文件 |

## 导出参数为什么是这几个值

| 参数 | 值 | 为什么 |
|---|---|---|
| `use_selection` | True | 一个部件一次导出，只导选中的东西 |
| `object_types` | `{ARMATURE, MESH}` | 就算误选，空物体 / 灯光 / 摄像机也不会进 fbx |
| `add_leaf_bones` | **False** | 不导出叶骨骼。开着会给每条链末端补一根 `<骨名>_end`（实测米娅 650 骨 → 799 根，多 149 根），UE 里多一层没用的层级 |
| `bake_anim` | **False** | 不导出动画。这个流程要的是 rest 状态的资产 |
| `apply_unit_scale` | True（Apply Unit） | 按场景单位写进 FBX：数字是厘米，元数据也是厘米，UE 读出来就是原尺寸 |
| `use_mesh_modifiers` | True | 普通修改器（细分、倒角…）在导出时应用；Armature 变形器由导出器自己处理，不会被烘死 |
| `embed_textures` | True | 贴图嵌进 fbx，不用另外拷图（实测鼓台 10 张图跟着进） |
| `mesh_smooth_type` | OFF | 不写平滑组，法线本身照常导出；UE 自己算法线 |
| `use_custom_props` / `use_tspace` | False | 不带自定义属性、不烘切线（UE 会重算） |
| 轴向 | 默认 `-Z forward / Y up` | Blender Z-up → FBX Y-up，UE 导入时再转 Z-up，标准组合 |

## 输出：manifest.json（这就是计划里要的「记录父级情况的文件」）

每个 fbx 一条，关键字段：

```json
{
  "file": "米娅-星彩_stick_L.fbx",
  "kind": "static",
  "parent": {"type": "bone", "bone": "左手首", "attach": "socket_zero_offset", "space": "bone_rest"},
  "meshes": [{
    "object": "stick_L_Mia",
    "parent_chain": ["stick_L_Mia", "H_L_Mia", "controller_root_Mia", "BB_Mia"],
    "resolution": {"type": "bone", "bone": "左手首", "matched_ancestor": "H_L_Mia",
                   "match_error_mm": 0.009, "match_rotation_deg": 0.0},
    "stability": {"frames": [12730, 14444], "translation_mm": 0.0, "rotation_deg": 0.0, "ok": true},
    "bake_matrix": [[...]],
    "bake_deviation_mm": 0.00006,
    "vertices": 77, "shape_keys": [], "materials": ["lambert1.001"]
  }],
  "bytes": 29468, "sha256": "…"
}
```

`parent.type` 只有三种，UE 那边的动作也就三种：

| `parent.type` | 意思 | 进 UE 怎么做 |
|---|---|---|
| `armature` | 人物本体，fbx 里带骨架 | 直接当 SkeletalMesh 导入，不要额外挂父级 |
| `bone` + `socket_zero_offset` | 顶点已经是骨骼空间坐标 | 挂到 `parent.bone`，**相对变换保持 0** |
| `world` + `place_at_origin` | 顶点已经是世界坐标 | 直接摆在原点 |

还有 `armature` / `units` / `export_options` / `gates` / `warnings` / `assembly`（后者是给「拼装」那一步看的
现成说明：哪些 fbx 是本体、哪些挂哪根骨、哪些摆原点）。

## 验收：把 fbx 导回来比

`fbx_verify.py` 会开一遍源文件把「每个部件在导出空间里该是什么坐标」算出来，再逐个 fbx 导回空场景比。
米娅这份文件的结果（92 项全过）：

| 检查 | 实测 |
|---|---|
| 骨名集合 | 650 根，一个不多一个不少（多出来的就是叶骨骼） |
| 骨骼 rest 矩阵 | 最大偏差 0.0057 mm（`左肩C`，float32 精度级别） |
| 骨骼网格逐顶点坐标 | 48550 点，最大偏差 0.0274 mm |
| 形态键 | 31 个名单一致；每个形态键的顶点坐标都单独比过，最大 0.126 mm |
| 蒙皮权重 | 48550 个顶点逐个比 (骨名, 权重)，组不匹配 0、最大权重差 0.00000 |
| 材质 / 贴图 | 32 个材质一致；标准材质的贴图都在（toon 材质的带不走，见坑 5） |
| 部件坐标 | 鼓棒 77 点最大 0.0277 mm；凳子 1266 点 0.0141 mm |
| 杂物 | 没有空物体 / 灯光 / 摄像机；`actions=0` |

0.03 mm 这个量级不是错，是 FBX 里顶点存 float32 的量化误差（坐标 100 左右，相对精度 1e-7）。
判据是 0.1 mm，正常都过。

## 踩过的坑（都实测过）

1. **叶骨骼**：`add_leaf_bones` 默认是 True，忘了关，每根链末端都会多一根 `_end` 骨
   （实测米娅 650 骨 → 799 根）。用骨名集合一验就现形。
2. **动画**：`bake_anim` 默认也是 True。忘了关，fbx 里会多出一堆 action，UE 导入时还要你选。
3. **姿势**：导骨骼网格前把骨架切 `REST`。不切，视口里是当前帧的演奏姿势，导出的是 rest——
   屏幕上看着对的其实不对，出问题很难查。
4. **形态键 + 修改器**：Blender 不能对带形态键的网格应用修改器。这种部件如果还挂着细分之类，
   导出时那个修改器会被跳过（`use_mesh_modifiers` 也救不了）。`fbx_analyze.py` 会在 `warning` 里点名。
5. **mmd_tools 的 toon 材质带不走贴图**：MMD 原装材质用的是 `mmd_shader` / `mmd_base_tex` 这类自建节点组，
   Blender 的 FBX 导出器找不到它们。实测米娅的 32 个身体材质、夜兰的 22 个全部如此，导出来的材质是纯色；
   而鼓台的 5 个材质是标准 `Principled BSDF + Image Texture`，10 张图正常带出。
   **这不是导出的 bug**，要带贴图得先把材质换成标准节点结构（或者进 UE 重做）。验收里对这类材质只报告、不判 FAIL。
6. **别用 `obj.bound_box` 判断位置**：它算的是**变形后**的包围盒。骨骼在姿势下，身体网格的 `bound_box` 是当前帧的
   样子（米娅在 12730 帧是 x[-24.8, 54.7]，而 rest 几何是 x[-60.3, 60.3]），拿它当基准会得出"导出错了"的错误结论。
   要比就比 `mesh.vertices` 的原始坐标。
7. **控制器方块会被当成部件**：它们是真 mesh。分类要靠「在控制器集合里 / 又小又光 / 挂约束」这几个证据，
   别只按名字（有的文件里方块叫 `H_L`，有的叫 `HP_L`，还有的叫 `Tar_Camera`）。
8. **父级断了的部件会静默变成静止物**：见前面 `夜兰_D.blend` 的 `stick_R_yelan`。一定看「提醒」那一节。
9. **一个 fbx 里不要混两类东西**：本体（带骨架）和乐器分开导。混在一起，UE 会把整个文件当一个骨骼网格处理。

## 与计划文档的差异（三条，都有实测依据）

1. **带形态键的部件，默认不连骨架导出。** 计划里写的是「armature + mesh」。实测：单导网格时 12 个
   shape key 一个不少；连骨架导，容积从 2.81 MB 涨到 3.48 MB，而这份网格本身**没有蒙皮**
   （导出后 `modifiers=[]`、`groups=0`），UE 那边它仍然是静态网格，骨架只是白带的。
   作者 2026-09 手工导的那批（`辛焱_DrumKit.fbx`）也是单导。真想让乐器拥有骨骼级形态键驱动，
   正确做法是给它蒙皮，而不是多带一份骨架——需要时加 `--morph-with-armature` 复现计划里的写法。
2. **用副本烘焙，不改源文件再还原。** 计划里是「加临时空物体 → 改父级 → 应用 → 导完还原」，
   这对手点是对的，但手点的还原顺序很容易错（约束、父级、删空物体三步）。脚本复制一份网格干这件事，
   导完就删，源物体一个字节都不动。数学完全一样（副本的物体矩阵设成烘焙矩阵再应用）。
3. **分类和父级判定走结构证据，不走命名约定。** 米娅的骨叫 `左手首`，夜兰的骨叫 `手首.L`，
   控制器有的叫 `H_L_Mia` 有的叫 `H_L_yelan`——靠名字写死规则换个模型就废。现在的判据是
   「世界矩阵和哪根骨重合」+「在不在控制器集合里」，两套文件都能直接跑（米娅 5 个 fbx 全过，夜兰 7 个部件判定合理）。
